# Project Ontology

## 1. Purpose

This document fixes the domain vocabulary, core entities, module boundaries, workflows, integrations, and invariants of SynCinema so that future planning sessions (Step 2, Step 3, Step 4, and any later replanning) use the same terms with the same meaning. It is derived entirely from repository evidence gathered during Step 1 and Step 1.5 of this ClaudeQB run; it is not a design aspiration.

## 2. Domain Vocabulary

- **Track / Audio Track** — one independent audio source (local file or URL) with its own offset, volume, EQ, compressor, gain boost, and output device. Represented by the `AudioTrack` interface in `src/types.ts`.
- **Offset** — a signed number of seconds a track's audio is shifted relative to the video clock (`AudioTrack.offset`). Positive means the audio starts later than the video.
- **Drift** — the observed difference between an audio element's actual `currentTime` and its computed target time (`videoCurrentTime - offset`). Corrected when it exceeds `syncThreshold` (default 0.3s), per `AudioTrackRow.tsx`.
- **Fingerprint** — a short string uniquely identifying a video or audio source without hashing file bytes (`getVideoFingerprint`/`getAudioFingerprint` in `src/utils/fileFingerprint.ts`). Prefixed by source type: `local_`, `yt_`, `gdrive_`, `url_`.
- **Sync Preset** — a community-contributed row in the Supabase `sync_presets` table pairing a `video_id`/`audio_id` (fingerprints) with an `offset_ms` and a `votes` count.
- **Trusted preset** — a sync preset with `votes > 1`; a single-vote preset is shown to the user as "unverified."
- **EQ Chain** — the fixed three-band Web Audio filter sequence per track: lowshelf (320 Hz) → peaking (1000 Hz, Q 0.5) → highshelf (3200 Hz), implemented in `AudioGraphManager.tsx`.
- **Gain Boost** — a post-EQ `GainNode` multiplier per track, range 1.0–3.0×.
- **Compressor Bypass** — the deliberate design where disabling the compressor rewires the audio graph (`high.connect(gain)` instead of routing through the `DynamicsCompressorNode`), rather than setting unity-gain parameters.
- **Device Routing** — per-track output device selection via `AudioContext.setSinkId()`; distinct from the video element's own `setSinkId()` for its own audio.
- **Project file (`.sync`)** — a user-downloadable JSON export/import format containing `trackPrefs` (keyed by filename) and `appSettings` (master volume, theme).
- **Detached player** — a second browser window (`detached.html` / `src/detached.tsx`) that mirrors playback state via a token-gated `BroadcastChannel` named `syncinema-player-sync`.
- **Session token** — a per-session random value generated by the main window and required on every `BroadcastChannel` message to prevent one tab's detached window from controlling another tab's session.

## 4. Module and Boundary Map

- **Sync/playback core** — `src/hooks/useVideoPlayer.ts`, `src/components/AudioTrackRow.tsx`. Owns the video clock and drift correction. This is the product's core domain and should remain the most protected/tested area.
- **Audio DSP** — `src/components/AudioGraphManager.tsx`. Owns one `AudioContext` per track; render-null component pattern.
- **Video rendering** — `src/components/VideoPlayer.tsx` (native `<video>`), `src/components/YouTubePlayer.tsx` (IFrame API). Both delegate subtitle rendering to the shared `src/components/SubtitleOverlay.tsx`.
- **Media ingestion** — `src/components/UrlLoaderModal.tsx`, `src/hooks/useAudioTracks.ts`, `src/hooks/useVideoPlayer.ts` (`loadVideoFromUrl`). Owns URL classification/conversion (YouTube, Google Drive, Dropbox, direct file).
- **Server proxy (only outbound server-side network boundary)** — `api/proxy.ts` (Vercel serverless function). Owns Google Drive virus-scan-bypass streaming, origin/referer checks, rate limiting, file-ID validation.
- **Cloud sync backend (only persistent backend boundary)** — `src/lib/supabase.ts`, `src/hooks/useCloudSync.ts`, `src/components/AdminPanel.tsx`, plus four RPC functions that exist only in the Supabase dashboard (not in this repository): `verify_admin_password`, `admin_delete_preset`, `safe_insert_preset`, `safe_increment_vote`.
- **i18n** — `src/i18n/*`, `src/context/I18nContext.tsx`. Self-contained; four languages (`en`, `tr`, `az`, `ru`).
- **State orchestration** — `src/App.tsx` composes five hooks (`useVideoPlayer`, `useAudioTracks`, `useTheme`, `useAnalytics`, `useCloudSync`) and distributes state through `src/components/Sidebar.tsx` to child sections in `src/components/sidebar/`.
- **Persistence boundary** — three distinct mechanisms, each scoped to a different data class: `localStorage` (UI prefs, per-file track prefs, local analytics), `.sync` files (user-owned project export), Supabase `sync_presets` table (only community-shared data leaves the browser).

## 5. Workflows and Lifecycles

**Playback sync workflow:** `VideoPlayer`/`YouTubePlayer` fires time updates → `App.tsx` updates `currentTime` (committed at 10 Hz, not every frame, per `useVideoPlayer.ts`'s `TIME_COMMIT_INTERVAL_MS`) → each `AudioTrackRow` computes `targetTime = videoCurrentTime - track.offset` → drift correction fires only when `|audioTime - targetTime| > syncThreshold`, throttled to once per 500ms.

**Device switch workflow:** User selects a new output device → `AudioGraphManager`'s device-switch effect calls `ctx.setSinkId(deviceId)` on the *existing* `AudioContext` — the context is never destroyed/recreated (a deliberate fix for a past audio-glitch bug, per README's "Design Decisions & Gotchas").

**Cloud sync discovery workflow:** Video + first audio track both resolve to fingerprints → `useCloudSync.findPreset` queries Supabase for the highest-voted preset for that pair → if the offset differs by >100ms from the current local offset, a toast with an "Apply" action is shown; if it matches, the track is silently marked cloud-synced; if no preset exists, nothing happens. Each fingerprint pair is only asked about once per session (`askedPresets` set in `App.tsx`).

**Cloud sync contribution workflow:** User shares an offset → `saveOrUpvotePreset` validates payload shape/bounds client-side, enforces a 5-second client-side cooldown, then either upvotes an existing preset within ±50ms (rounded to nearest 100ms) via `safe_increment_vote`, or inserts a new one via `safe_insert_preset`. Both RPCs additionally enforce server-side limits, per `supabase/README.md`.

**Admin moderation workflow:** `Ctrl+Shift+A` (desktop) or `?admin=true` URL param (mobile, stripped immediately) opens `AdminPanel` → password submitted to `verify_admin_password` RPC → on success, all `sync_presets` rows are fetched and deletable via `admin_delete_preset`. Client-side lockout after 3 failed attempts (30s) exists but does not prevent direct RPC calls with the anon key (see Autopsy AUTOPSY-P1-01).

**Detached player handshake:** Main window generates a session token → opens `/detached.html?token=...` → detached window reads the token from its URL and rejects any `BroadcastChannel` message whose `token` field does not match.

**Project save/load lifecycle:** `exportProject` bundles all stored track prefs (from `localStorage`) plus `masterVolume`/`theme` into a downloadable `.sync` JSON file. `importProject` reads the file, writes it back to `localStorage`, and applies matching prefs to any currently-loaded tracks by filename — with no schema validation before the values are spread onto live state (see Autopsy AUTOPSY-P2-03).

## 6. Integrations and External Systems

- **YouTube IFrame API** — loaded dynamically once per app lifetime (`YouTubePlayer.tsx`); polled every 500ms for time updates (no push API available); cannot route audio to a specific output device (platform limitation, correctly surfaced to the user in-UI).
- **Google Drive** — accessed only through `api/proxy.ts`, which handles Google's virus-scan interstitial page by extracting a confirmation token and retrying, with Range-header forwarding for seekable playback.
- **Dropbox** — client-side URL rewriting only (`?dl=0` → `?dl=1`); no server involvement.
- **Supabase (Postgres + RPC)** — the only persistent backend; anon key is intentionally public (standard Supabase model); four RPCs are the entire server-side authorization surface and are **not version-controlled in this repository** (see Autopsy AUTOPSY-P1-02).
- **Vercel** — hosts both the static build and the `api/proxy.ts` serverless function; `vercel.json` also carries the CSP and security headers for the whole app.
- **Browser Web APIs relied upon as integration points:** Web Audio API (`AudioContext`, `setSinkId`), Media Devices API (`getUserMedia`, `enumerateDevices`), `BroadcastChannel`, `File`/`FileReader`, Fullscreen API, Picture-in-Picture (referenced in a reverted commit per git history — currently uses a custom detached window instead).

## 7. Invariants and Constraints

- **One `AudioContext` per audio track, created once, never destroyed on device change.** Recreating it on device switch was a past bug (per README) and must not be reintroduced.
- **Compressor bypass must remain a graph rewire, not a parameter trick.** Setting `ratio=1`/`threshold=0` still audibly affects signal; the correct bypass is `disconnect()`/`connect()` around the compressor node.
- **`currentTime` commits to React state at 10 Hz, not 60 Hz**, to avoid a full app re-render on every animation frame; any future change to the sync loop must preserve this throttling or explicitly re-justify removing it.
- **Track prefs are keyed by filename, not by fingerprint, in `localStorage`.** This is intentional (same-filename reload is the dominant use case) and must not be silently "fixed" to use fingerprints without recognizing this trade-off.
- **The Google Drive proxy only accepts file IDs matching `^[a-zA-Z0-9_-]{28,44}$`.** Any change to Google Drive URL handling must preserve input validation before the ID reaches an outbound `fetch`.
- **The app must remain fully functional with `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` absent** (`supabase` client becomes `null`, all cloud-sync features silently no-op). This invariant must not be broken by future cloud-sync work.
- **The product is web-based only; no native mobile app is planned**, per the explicit Step 1 intake decision — the core value proposition (per-track output-device routing) is not deliverable with parity on mobile OS audio stacks.
- **Bookmarklet/URL-param video loading only accepts `http(s)://` schemes**, rejecting `javascript:`, `data:`, `file:` — this validation must be preserved in any future change to that flow.

## 8. Open Ontology Questions

### Competency Questions

- **Is the CSP `media-src` allowlist actually compatible with Dropbox/generic-HTTPS sources the UI advertises?** — status: `open`. Requires a live browser test (flagged in Autopsy AUTOPSY-P2-01 / Main-Planing.md Phase 3).
- **Does `eqPresets.ts` fully define the preset-matching logic referenced by `getCurrentPresetId` in `AudioTrackRow.tsx`?** — status: `answered`. `src/constants/eqPresets.ts` defines six fixed integer-valued presets (`flat`, `cinema`, `dialogue`, `music`, `night`, `bass`) and `getCurrentPresetId` matches by exact equality on `{low, mid, high}`. This is a pure, side-effect-free function with no floating-point tolerance concerns (all preset values are whole numbers), making it one of the lowest-risk, highest-value first targets for Phase 4 unit testing.
- **Is there any CI, branch protection, or remote-only configuration on the GitHub repository that a local clone cannot reveal?** — status: `open`. Cannot be verified without remote/dashboard access.
- **Does the current single in-memory rate limiter in `api/proxy.ts` need to become distributed (e.g., Redis-backed) before Phase 6/7, or is it acceptable indefinitely at expected traffic levels?** — status: `open`. Depends on future traffic, which is unknown.
- **Should `.sync` file import validation (Autopsy AUTOPSY-P2-03) reject unknown fields entirely, or merge permissively while only whitelisting known keys?** — status: `open`. A Step 2/4 design decision, not yet made.
